# PC-003 — Auditoría consistente para todas las mutaciones

Prioridad: P0
Estado: Pendiente

## Encargo y criterios de aceptación

**Dependencias:** PC-000. Esta base debe estar antes de los cambios de saldos, cantidades y documentos.

**Archivos:** `server/store.mjs`, `server/api.mjs`, `server/floor.mjs`, `server/documents.mjs`, `server/receipts.mjs`, `server/fleet.mjs` según operaciones afectadas.

**Trabajo:** ampliar `audit_log`, sin crear un historial paralelo. Contrato lógico: identificador, instante UTC, actor estable de la sesión, nombre visible, rol, acción, categoría, entidad/ID, campos cambiados, antes/después, motivo y operación de origen. Usar una lista explícita de campos permitidos para evitar registrar contraseñas, tokens o imágenes.

**Aceptación:** modificación y evento se guardan en la misma transacción cuando comparten base; ningún cambio exitoso crítico queda sin evento. Los reintentos no duplican movimientos comerciales. Diferenciar intentos fallidos de cambios efectivos. Los usuarios comunes no pueden editar ni borrar la auditoría. Registros viejos mantienen su autor textual; no inventar un ID histórico a partir de un nombre ambiguo.

**Pruebas:** dos cuentas con nombre igual, sesión manipulada, rollback de operación, reintento, cambio de precios y saldo. Añadir consulta paginada con filtros e índices justificados para PC-014.
