## Encargo y criterios de aceptación

**Dependencias:** tickets de implementación incluidos en cada entrega. Repetir la verificación pertinente por lote; no esperar a terminar todo para comprobar integración.

**Trabajo:** ejecutar el circuito completo con administración y repartidor: crear pedido mixto → pesar con cajas/bolsa → asignar → localizar mediante filtro → iniciar una sola vez → entregar/cobrar → corregir saldo → revisar movimientos → emitir hoja de ruta → eliminar un documento de prueba. Agregar una repetición con pérdida de red y dos usuarios.

**Aceptación:** cálculos consistentes en UI/API/base/PDF, permisos comprobados, sin errores de consola nuevos ni pérdida de formularios. Los cambios de contratos se integran antes de publicar. Mantener evidencia por criterio, diff, migraciones, instrucciones de aplicación y recuperación. Un ticket con plantilla o prueba física pendiente queda en revisión/bloqueado para esa parte, no “Hecho”.

**Comandos existentes:**

```bash
npm test
npm run build
npm run test:e2e
npm run test:a11y
```

Verificar dependencias, navegador de pruebas, variables, puertos y directorios aislados antes de correrlos. El proyecto no declara un script `lint`: no informar que pasó ni inventar ese comando. `npm run format` modifica muchos archivos; no usarlo indiscriminadamente sobre cambios ajenos. Ejecutar comprobaciones focalizadas durante el ticket y las integradas al preparar la entrega; no repetir pruebas sin una razón pendiente.
